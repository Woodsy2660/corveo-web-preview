# Corveo BP Basics: Lovable handoff

Package v0.1 | Prepared 16 September 2026 | Private prototype input, not a published product

## Use this package

Unzip the archive. Open the existing Corveo Lovable project when available; otherwise create a new design project. Attach `01_LOVABLE_MASTER_PROMPT.md`, `02_CONTENT_ALL_SIX_WEEKS.json`, and `04_FICTIONAL_READINGS.json`, plus the relevant reference images. Then paste the contents of `00_PASTE_INTO_LOVABLE.txt` into the project chat. The implementation handoff can be attached with the initial inputs or in the readings/build pass.

Do not upload the archive as the only input and assume every nested file has been read. Attach the actual files needed for the pass. The master Markdown contains all six complete chapter bodies, so there is no need to find or copy text from earlier chats. The structured content JSON contains the same draft text and useful metadata.

A first pass should render the complete index and every chapter in website and app treatments. A second pass can complete the readings interactions if needed. The full specification remains the destination: stopping at the programme screens is not completion of the requested app preview.

## What is complete and what is not

All six BP Basics chapters are present in full, with summaries, standfirsts, headings, bylines, exact takeaways, image concepts and review notes. Weeks 1, 2, 3, 5 and 6 come from the prior chat draft. Week 4 comes from the supplied v0.7 Appendix A. This is a packaging and prototyping pass, not a new medical evidence review.

The six Pulse and four In Focus entries have complete catalogue coverage, but their ten independent article bodies are not supplied. The prototype must identify those missing texts rather than invent them.

The fonts Spectral, Hanken Grotesk and IBM Plex Mono are explicitly declared in an older Corveo HTML framework. They are a documented starting point, not a verified identification of the current app's font files. Existing project CSS takes precedence.

Week 4 retains unresolved source reassurance wording and must carry a visible editorial-review hold. Week 3's locked takeaway is also flagged. All clinical review remains pending. Do not distribute the prototype as patient guidance.

The fictional records demonstrate layout and interactions only. Real HealthKit authorisation/ingestion, native app delivery, production storage, privacy/security controls, approved CMS mapping and regulatory review are separate work. The readings fixture must not be interpreted as a recommended measurement schedule or set of targets.

## Supplied versus proposed

Source-derived: six titles/order, requested byline, draft chapter text, locked takeaways, editorial titles/link direction, earlier font declarations and photographed visual treatments.

New prototype proposals: route names, responsive component arrangement, short programme description, chart/filter interactions, fixture data, local keys and presentation fields. These are not approved Corveo production schemas or clinical algorithms.

## Before sharing the preview

Check the actual project's access settings; a draft label or no-index tag is not an access restriction. Keep the work within the authorised review group, use fictional entries only and do not publish it. Do not load real patient information into this design project.
